# v2.5.8: Shorter Alarm Durations, Backup Data Loss Fixes, and Cross-Platform Parity

## Summary of Changes
Release v2.5.8 introduces shorter alarm ring duration options ("Ring Once" and "15 Seconds"), fixes critical data loss during backup restoration where dose notes and user preferences were omitted, resolves a schedule dosage desynchronization bug when editing medications, fixes undoing as-needed (PRN) doses, achieves 100% translation and format specifier parity across all 12 locales, and aligns the cross-platform OpenAPI 3.0 specification with Android Room database models.

> **⚠️ Note for existing GitHub APK users**:
> Because Dosezy v2.4.2+ transitions to our official production release signing key (required for Google Play), updating directly over older debug-signed APKs requires a quick backup & reinstall:
> 1. In Dosezy, go to **Menu → Backup & Restore** and tap **Export/Create Backup**.
> 2. Uninstall the older version.
> 3. Install the new **v2.5.8** APK.
> 4. Go to **Menu → Backup & Restore** and tap **Restore Backup** to restore all profiles, medicines, and history in 1 tap.

---

## 📱 Patient App (Android)

* **Shorter Alarm Ring Duration Options**:
  - Added **Ring Once** (`-1`) and **15 Seconds** (`15s`) options to Alarm Ring Duration preferences, complementing existing continuous, 30s, 1m, 2m, and 5m options.
  - Implemented single-shot audio completion listener for `MediaPlayer` and `RingtoneManager` along with single-pulse vibration waveforms (`repeatIndex = -1`) when "Ring Once" is selected.
  - Fully translated duration labels across all 12 supported locales.
* **Fix Backup Restore Data Loss**:
  - Resolved a critical data omission in `BackupRestoreManager.parseUserFromJson()` where `allowDoseSkipping`, `allowCustomDoseTime`, `hideAddMedicineNavButton`, `allowDoseUndo`, `allowDoseNotes`, and `promptDoseNotes` were not deserialized, causing restored profiles to silently reset preferences.
  - Fixed `parseSchedulesFromJson()` to restore `doseNotes`, ensuring patient symptom notes, food context, and meal records are fully preserved across backup cycles.
* **Fix Schedule Dosage Desynchronization on Medicine Edit**:
  - Updated `MedicineRepository.updateMedicine()` to detect changes in `dosage` and `customDosages`.
  - Modifying a medication's dosage or time-slot amounts now immediately regenerates future pending schedule entries with the updated dosage.
* **Fix As-Needed (PRN) Dose Undo**:
  - Fixed `ScheduleRepository.undoDoseTaken()` to delete dynamic `PRN_` entries from Room rather than resetting them to `PENDING`, eliminating phantom pending records on the home screen.
* **Data Exporter Parity**:
  - Updated `DataExporter.buildJsonContent()` to export all user preferences, custom dosages, schedule dosages, and dose notes.
  - Added `Dosage` and `Dose Notes` columns to the `SCHEDULES` section in `buildCsvContent()`.
* **Locales and Translations 100% Parity**:
  - Re-aligned `import_profiles_found` across all 11 translated locales to match English non-parameterized text.
  - Escaped single apostrophes in French and Italian (`l\'archive`, `nell\'archivio`) to prevent resource compilation errors.
  - Added `formatted="false"` across all 12 locales for strings containing literal percentage signs.

## 🔌 API & Cross-Platform Parity

* **OpenAPI 3.0 Full Schema Parity**:
  - Added `allowDoseNotes` to `User` and `UserCreateInput` schemas in `api/openapi.yaml`.
  - Updated `alarmDurationSeconds` descriptions to include `-1` (Ring Once) and `15` seconds.
  - Updated `api/README.md` to document complete 100% field mapping and bidirectional data mappers between Room database models and network DTOs.
  - Bumped `/health` check response example version to `2.5.8`.
